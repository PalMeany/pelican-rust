# 0020. PHP-sidecar для оригинальных плагинов (M8)

**Статус:** Accepted (реализовано в M8; детали — `docs/plugins.md`)

**Контекст.** Плагин Pelican — Composer-пакет для Laravel/Filament: service providers, страницы и ресурсы
Filament трёх панелей, маршруты, миграции, слушатели событий, реестры (`TaskSchemaInterface`, features,
аватары, права, OAuth/captcha), и всё это напрямую использует `App\Models`, `App\Services` и Filament
оригинала. «Урезанный Laravel» такие плагины не исполнит — им нужен весь код панели той же версии.
pelican-rs не использует PHP-форматы сессий/очередей (0009) и не мигрирует схему (0003).

**Решение.**
- **Sidecar — сам оригинал** той версии, которой соответствует схема БД (обычно прежняя установка,
  с которой переезжают, или образ `ghcr.io/pelican-dev/panel` этой версии): тот же `.env` (БД, APP_KEY),
  общие `plugins/` и `storage/plugins`, собственный `vendor/` (composer-пакеты плагинов). pelican-rs
  запускает и контролирует его (`PANEL_PHP_SIDECAR=<путь|url>`) только если есть включённые PHP-плагины;
  слушает только loopback/unix-сокет. Версия сверяется при старте (`config('app.version')` ↔ наша
  эмулируемая); при расхождении PHP-плагины получают статус `errored`.
- **Мост** — плагин Pelican `pelican-rs-bridge` (папка в `plugins/` sidecar; оригинал не меняется, в списке
  плагинов pelican-rs скрыт). Его service provider регистрирует служебные маршруты, а Filament-плагин во всех
  панелях добавляет persistent-middleware (до `Authenticate`, действует и на `/livewire/update`):
  - `GET /_bridge/manifest`: что зарегистрировали PHP-плагины — маршруты (по namespace плагина),
    страницы/ресурсы Filament по панелям со slug'ами и навигацией, реестры (типы задач, features,
    провайдеры аватаров, права ролей/сабюзеров, ресурсы API-ключей).
  - `POST /_bridge/event`: событие от pelican-rs → Laravel `event()` только для слушателей плагинов
    (`ActivityLogged` по id, `eloquent.*` по id или из `toArray()` для удалённых, прочие `App\Events\*`);
    `DispatchWebhooks` оригинала на время такого вызова снимается — вебхуки доставляет pelican-rs.
  - `POST /_bridge/task`: выполнить задачу расписания типа из плагина.
  - Аутентификация: заголовок `X-Pelican-Rs-User: <id>` + HMAC от секрета, выведенного из APP_KEY
    (`hmac("pelican-rs-sidecar", key)`); middleware моста логинит пользователя в собственную сессию
    sidecar (`SESSION_DRIVER=file`, своё имя cookie — таблицу `sessions` занимает pelican-rs). Входящие
    от клиента `X-Pelican-Rs-*` pelican-rs вырезает.
  - Из расписания sidecar убираются задачи ядра (их выполняет pelican-rs), остаются задачи плагинов;
    очередь sidecar — `sync`.
- **Маршрутизация в pelican-rs:** таблица из манифеста — пути маршрутов плагинов и страниц Filament
  (`/admin/<slug>`, `/server/{server}/<slug>`, ...) плюс служебные `/livewire/*`, `/css|js/filament/*`,
  ассеты плагинов — проксируются в sidecar как есть (страницы плагинов выглядят как в оригинале; их
  навигация ведёт на те же URL, которые обслуживает pelican-rs). Пункты навигации плагинов добавляются в
  меню pelican-rs; реестры объединяются с WASM-реестрами (ADR-0018). Sidecar недоступен → 503 на его
  путях, ядро не затронуто.
- **Жизненный цикл:** install/update/uninstall/enable/disable PHP-плагина — `php artisan p:plugin:*` в
  sidecar (composer-пакеты, миграции, сидеры плагина как в оригинале), затем перечитывание манифеста.
  PHP-FPM поднимает приложение на каждый запрос, перезапуск процесса не нужен.
- **Без PHP:** плагины-языки (`category: language`) — только `lang/`; pelican-rs подключает их сам.
- **Обратное направление** (запись моделей кодом плагина в sidecar → WASM-плагины и вебхуки): вебхуки
  sidecar доставляет сам (его `DispatchWebhooks` для собственных записей остаётся); пересылка
  `eloquent.*` в рантайм WASM — по необходимости позже.

**Уточнения по реализации.**
- Подпись проксируемых запросов покрывает только время и пользователя (`PROXY`, `/`): Livewire повторяет
  middleware страницы на запросе, пересобранном из исходной страницы, — метод и путь там другие. Служебные
  `/_bridge/*` подписываются строго (метод, путь, тело).
- Вход в sidecar — `Auth::setUser()` на каждый запрос, без `Auth::login()`: событие `Login` оригинал пишет в
  журнал активности (дубль входа, уже записанного pelican-rs).
- Маршруты Livewire (в Livewire 4 — с хешированным префиксом) и выгрузки Filament приходят в манифесте
  (`framework_routes`); статические пути `/build/`, `/css/`, `/js/`, `/fonts/`, `/vendor/` проксируются как есть.
- `ActivityLogged` уходит в sidecar с атрибутами строки: она может быть ещё не закоммичена.
- Языковые плагины: мост отдаёт их `lang/` (PHP-массивы и JSON), pelican-rs накладывает переводы поверх своих.

**Вне M8:** server features PHP-плагинов (их модалки — действия Filament на странице консоли оригинала), темы Filament для UI pelican-rs, OAuth/captcha-провайдеры из PHP-плагинов, виджеты плагинов
на страницах ядра.

**Последствия.** Полная совместимость PHP-плагинов ценой процесса PHP рядом с панелью и двух стилей UI
(страницы плагинов — Filament). Без PHP-плагинов sidecar не запускается и ничего не стоит. Синхронизация
версий sidecar и схемы — ответственность администратора (проверяется при старте).
