# 0003. Схема БД: без собственных миграций

**Статус:** Accepted

**Контекст.** Критерий №1 — работа на существующей БД без миграции данных. Схема оригинала —
результат 255 миграций Laravel, физически разная на MySQL, MariaDB, PostgreSQL и SQLite.

**Решение.**
- Rust-панель не меняет схему существующей БД. При старте сверяет таблицу `migrations` со списком
  миграций оригинала (`crates/pelican-db/schema/migrations.txt`): не хватает → отказ с понятной
  ошибкой («обновите БД оригинальной панелью до версии X»); лишние (новее/плагины) → предупреждение.
- Новая установка: исполняются дампы схемы, снятые с оригинала в Docker для каждой СУБД
  (`scripts/schema/refresh.sh` → `crates/pelican-db/schema/{mysql,mariadb,pgsql,sqlite}.sql`),
  в `migrations` записываются все миграции с `batch = 1`, плюс сид-строки, которые пишут сами
  миграции (`backup_hosts` «Local»). Оригинальная панель может «принять» такую БД.
- Своих таблиц не добавляем (сессии — в существующей `sessions`, см. 0009).

**Последствия.** Обновление схемы при выходе новых версий оригинала = перегенерация дампов и
сущностей. `DB_PREFIX` (префикс таблиц) не поддерживается в MVP (QUESTIONS Q4).
