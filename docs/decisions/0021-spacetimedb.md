# 0021. SpacetimeDB: оценка (QUESTIONS Q1)

**Статус:** Deferred (2026-10-15: решено пока не делать; к варианту 2 можно вернуться)

**Контекст.** На Q1 («какие СУБД») ответ — «как оригинал + можно добавить SpacetimeDB». SpacetimeDB (2.x) —
СУБД со встроенной логикой: таблицы и «редьюсеры» описываются в WASM-модуле (Rust/C#/TS), клиенты по WebSocket
подписываются на запросы и получают изменения строк в реальном времени. SQL — подмножество: два диалекта (запросы
через CLI/HTTP и подписки), только inner join, подписка возвращает строки одной таблицы с ограничениями на join
по индексам, DML в подписках нет; составные типы в SQL недоступны. Драйвера для sea-orm нет.

Слой данных pelican-rs (ADR-0004, 0011) — sea-orm + сырой SQL «в форме Eloquent» (~100 файлов): LEFT JOIN,
агрегаты, JSON-колонки, транзакции, точные форматы значений четырёх СУБД. Главное требование — работа на
существующей БД оригинала без миграции.

**Варианты.**
1. *SpacetimeDB как основной бэкенд.* Нужны схема в модуле, перенос данных из SQL (нарушает «без миграции»
   как основной путь), переписывание всего слоя данных на редьюсеры/подмножество SQL, потеря совместной
   работы с оригиналом и его плагинами на той же БД (ADR-0020). Объём — порядка нового проекта. **Отклонено.**
2. *Зеркало для реального времени (рекомендуется, опционально).* SQL-БД остаётся источником истины;
   выбранные таблицы (servers, allocations, schedules/tasks, activity_logs, backups) односторонне
   реплицируются в модуль SpacetimeDB: начальный снимок + изменения через шину событий моделей (ADR-0019,
   уже вызывается во всех путях записи). Клиенты (свой UI, боты, внешние панели) подписываются на живые данные
   без опроса API. Права — фильтры видимости строк модуля (владелец/сабюзер/админ), идентичность —
   токен, выдаваемый pelican-rs. Объём: модуль на Rust + синхронизатор + выдача токенов; без изменений ядра.
3. *Ничего не делать.* Живые данные серверов уже идут из websocket Wings; UI обходится htmx-опросами.

**Решение (предложение).** Вариант 2 как необязательная возможность после M8 (`PANEL_SPACETIMEDB_URL`), начиная
со спайка: проверка фильтров видимости под модель прав сабюзеров, задержек репликации и восстановления после
разрыва (повторный снимок). Вариант 1 не рассматривается, пока требование «без миграции» в силе.

**Последствия.** Совместимость с оригиналом не затрагивается; SpacetimeDB — дополнительный сервис для тех, кому
нужны подписки. Риски: соответствие фильтров видимости правам панели, рассинхронизация при пропущенных
событиях (лечится периодическим сверочным снимком), зрелость протокола подписок (v1/v2 в 2026 г.).
