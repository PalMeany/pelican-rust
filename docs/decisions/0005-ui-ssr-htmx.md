# 0005. UI: SSR (minijinja) + htmx + декларативные ресурсы

**Статус:** Accepted

**Контекст.** Оригинальный UI — Filament (серверный рендер Livewire): десятки CRUD-ресурсов, описанных
декларативно (таблица/форма/действия), плагины регистрируют ресурсы/страницы/виджеты. Нужен
функциональный паритет, не пиксельный. Рассмотрены: Leptos (CSR/SSR+hydration), SPA на TS, SSR+htmx.

**Решение.** Серверный рендер на axum + minijinja (шаблоны в рантайме — нужны плагинам и темам),
интерактивность через htmx; «острова» JS только там, где без них нельзя: консоль (xterm.js + WebSocket
Wings), редактор файлов (CodeMirror 6), графики ресурсов. Админка строится из декларативных описаний
ресурсов в Rust (`Resource { table, form, actions }`), которые рендерятся общими шаблонами — тот же
принцип, что у Filament.

**Почему не Leptos:** WASM-сборка и гидрация усложняют toolchain и делегирование, API Leptos часто
меняется; плагинам (WASM) пришлось бы поставлять UI-код в WASM-фронтенд. Декларативные схемы
плагин описывает данными через WIT-API, хост рендерит.
**Почему не SPA на TS:** второй язык и toolchain; админские операции всё равно требуют внутреннего API.

**Последствия.** Один язык, быстрая компиляция, нет WASM-фронтенд-сборки; UI-логика переиспользует
доменные сервисы напрямую. Клиентские JS-библиотеки вендорятся в `crates/pelican-web/assets`.
