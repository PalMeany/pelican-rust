# 0018. Плагины: формат и жизненный цикл оригинала + WASM-компоненты (wasmtime)

**Статус:** Accepted (уточняет ADR-0008)

**Контекст.** Плагин оригинала — папка `plugins/<id>/` с `plugin.json` и PHP-кодом, который Laravel грузит
в процесс (провайдеры, Filament-плагин, миграции, переводы). Состояние (`meta.status`, `load_order`) живёт в
самом `plugin.json`, таблицы нет. Операторская часть (импорт zip, установка, обновление по фиду, Hub,
Application API `/plugins`, админка) от PHP почти не зависит; исполняемая — целиком PHP (spec/plugins.md §9).

**Решение.**
1. *Операторская часть — как в оригинале, байт в байт.* Тот же каталог `plugins/`, схема `plugin.json`
   (неизвестные ключи сохраняются, запись `JSON_PRETTY_PRINT | JSON_UNESCAPED_SLASHES`), статусы
   (`not_installed/disabled/enabled/errored/incompatible/crashed`), предикаты, проверка `panel_version`
   (caret-таблица из `PluginCompatibilityTest`), безопасный импорт zip (лимиты, traversal, `.import-*`, откат
   `.<id>.bak`), фид обновлений с sha256, порядок загрузки, Hub (`X-Panel-Api-Key` только своему origin),
   Application API `/api/application/plugins` и страница `/admin/plugins`. Покрывается диф-тестами.
2. *Исполняемая часть — WASM-компонент.* Плагин объявляет компонент новым ключом манифеста
   `"wasm": {"component": "plugin.wasm", "api": 1, "capabilities": {...}}` (оригинал его игнорирует и
   сохраняет). PHP-плагины (`namespace/class` без `wasm`) управляются так же, но не исполняются: при
   загрузке они получают `status_message` «требует PHP-sidecar» (статус не меняется, чтобы не расходиться
   с оригиналом на тех же файлах); исполнение — M8.
3. *Хост:* wasmtime + component model, WIT-мир `pelican:plugin/plugin@1`. Экземпляр на плагин, вызовы
   сериализуются (Mutex), лимиты: fuel/epoch-interruption на вызов, память (`StoreLimits`), таймаут.
   Паника/трап плагина = `errored` (с сообщением), повторный трап при загрузке = `crashed` + уведомление
   Root Admin, как `handlePluginCrash`. `PANEL_PLUGIN_SAFE_MODE` отключает загрузку.
4. *Экспорты плагина (хуки):* `register() -> registration` (что плагин предоставляет), события панели и
   моделей (`on-event(name, json)`), HTTP-маршруты под `/api/client/plugins/<id>/…`,
   `/api/application/plugins/<id>/…` (с проверками ключа/прав хоста) и `/plugins/<id>/…` (веб),
   страницы и пункты навигации admin/app/server (HTML-фрагмент в общем каркасе страницы, разметка
   экранируется хостом, кроме явно помеченной), настройки (декларативная форма + `save-settings`),
   реестры: аватары, типы задач расписаний, server features (listeners + действие), типы вебхуков,
   капча; права (модели админ-ролей, группы прав сабюзеров, ресурсы API-ключей); переводы — файлы
   `lang/<locale>/*.json` в папке плагина (неймспейс `<id>::`, у `language` — глобальные).
5. *Импорты (возможности хоста), выдаются по `capabilities`:* лог, KV-хранилище плагина
   (`plugins/<id>/.data/kv.json`, ответ на открытый вопрос §6 спецификации), исходящий HTTP по allowlist
   хостов, вызовы API панели от имени плагина (внутренний вызов роутеров Client/Application API с ACL,
   ограниченным манифестом), запись активити, уведомления. Прямого доступа к БД и ФС нет.
   Возможность `api` реализована настоящим application-ключом плагина (memo `Plugin: <id>`, владелец — первый
   Root Admin, права = `capabilities.api`, пересинхронизируются при изменении манифеста): ключ виден и отзывается
   в списке API-ключей, вызовы проходят обычный конвейер Application API и попадают в активити с этим ключом;
   секрет хранится в `storage/plugins/<id>/api-key.json`, вне досягаемости плагина.
6. *События моделей:* общий шина `model_events` (`eloquent.created/updated/deleted: App\Models\X`) —
   и для вебхуков (недостающий хвост M5), и для `on-event` плагинов.
7. *SDK:* крейт `pelican-plugin-sdk` (wit-bindgen, Rust → `wasm32-wasip2`), пример плагина и
   `p:plugin:make`-аналог в CLI.

**Последствия.** Файлы плагинов совместимы в обе стороны; PHP-плагины видны и управляемы, но до M8 не
работают. Поверхность хуков меньше Filament (произвольные Livewire/Blade недоступны) — расширяется
версией WIT-мира (`api`), старые версии мира поддерживаются адаптерами.
